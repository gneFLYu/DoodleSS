## 1. Yes, synchronize the spectral sequences—but as a comparison diagram

Your attached Tate diagram is the correct blueprint. It comes from maps of filtered towers, giving

\[
\mathrm{SliceSS}(X)\longrightarrow\mathrm{HFPSS}(X)
\longrightarrow\mathrm{TateSS}(X)
\]

and the corresponding HOSS/LSliceSS row. The important phrase is **isomorphism in a specified region**, not global equality. This is how the comparison is used in [Duan–Li–Shi](https://arxiv.org/abs/2204.08600) and in the [RO\((G)\)-graded Morava \(E\)-theory calculation](https://par.nsf.gov/servlets/purl/10626405).

We should therefore keep each spectral sequence in its own native workspace and connect them by typed comparison maps. Do not copy an entire TateSS or SliceSS chart into HFPSS.

For a target period \(P\) and comparison \(\phi:E_r^{H}\to E_{r'}^{T}\), a proposed HFPSS translation is legitimate only when:

1. \(\phi\) is an isomorphism—or has the required injectivity/surjectivity—at both the original and translated grades;
2. \(\phi(x)P^n\) remains inside that comparison region;
3. \(\phi(x)P^n\) lies in the image of \(\phi\);
4. its preimage is unique modulo a controlled kernel;
5. the page and differential-degree conventions are compatible.

Then Studio can record

\[
x' = \phi^{-1}(\phi(x)P^n)
\]

as a **pullback-period certificate**. If only the target period is known but the inverse comparison is unavailable, it remains a pseudo-period suggestion, not an HFPSS identity.

| Comparison situation | Studio result |
|---|---|
| Isomorphism at both grades, target period in range | Certified pulled-back translation |
| Only injective | Target equality can detect an HFPSS equality, but cannot construct every preimage |
| Only surjective | A preimage may exist but can be nonunique modulo the kernel |
| Outside the theorem’s cone/range | Review-only visual motif |
| Period crosses a \(v_1\)-exception or differential | Blocked instance with the obstruction displayed |

This is not computationally expensive at our scale. The current project has only **19 workspaces, 80 classes, 26 differentials, and 5 comparison records**. Sparse grade indexes and virtual translations make lookup cheap. The costly part is mathematical curation: encoding the exact cones, page ranges, normalizations, kernels, and source propositions. Large SliceSS regions can eventually become sizeable, but lazy loading and virtual period orbits avoid materializing infinite charts.

The current model is not yet sufficient. [Comparison](</E:/课程/PACE2025_fly/HFPSS Q_8/DoodleSS/HFPSS-Studio/backend/domain/models.py:193>) stores only a source, target, grade shift, mode, notes, and source reference. - `page_map` and differential-degree convention;
- `grade_map`, not merely one fixed shift;

## 2. The \(\mathbb F_4\) cell should use projective directions, not simplex geometry

For a rank-two cell with basis \(a,b\), the relevant one-dimensional directions form

\[
\mathbf P^1(\mathbb F_4)
=\{[1:0],[0:1],[1:1],[1:\zeta],[1:\zeta^2]\}.
\]

Thus \(a+b\), \(a+\zeta b\), and \(a+\zeta^2b\) are three distinct directions. Scalar multiples are the same direction: \(v\) and \(\zeta v\) should share one projective port after normalizing the first nonzero coordinate to \(1\).

Consequently, an arrow

\[
d_r(x)=a+\zeta b
\]

should terminate at a labelled port `[1:ζ]`, not at an undifferentiated geometric segment. For rank three there are already \((4^3-1)/(4-1)=21\) projective directions, so Studio should not draw every possible direction. It should render the chosen basis dots and create combination ports on demand for vectors that actually occur in a differential, relation, or proof.

This is the immediate missing backend object:

```text
CellVectorSpace(field=F4, canonical_basis, display_basis, change_matrix)
DifferentialMap(source_cell, target_cell, F4_matrix)
PageTransition(kernel, image, quotient, next_basis)
```

## 3. Macaulay2 would help, but it should remain optional

You do **not** need to provide one for the first useful implementation: exact \(\mathbb F_4\) arithmetic is already native, and Gaussian elimination, kernel/image, quotient bases, and small Gröbner reductions can be deterministic Python code.

Macaulay2 supports noninteractive `M2 --script` execution, and its official JSON package supplies `fromJSON`/`toJSON`, which gives us a clean adapter boundary: [command-line scripting](https://macaulay2.com/doc/Macaulay2/share/doc/Macaulay2/Macaulay2Doc/html/_invoking_spthe_sp__Macaulay2_spprogram.html), [JSON package](https://macaulay2.com/doc/Macaulay2/share/doc/Macaulay2/JSON/html/index.html).
